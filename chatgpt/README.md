# Compare Two Texts — ChatGPT pilot 0.2.1

Приватное MCP-приложение для сравнения двух прикреплённых документов и просмотра изменений прямо в ChatGPT. Версия 0.2 добавляет DOCX, PDF с текстовым слоем и TXT. Существующий режим точного сравнения строк, выборочного применения правок и TXT-экспорта сохранён.

Адаптер использует модули CTT из `src/`: импорт документов, выравнивание блоков, пословный diff, PDF.js и визуальную модель DOCX. Основной сайт и расширения CTT развёртываются отдельно.

## Сценарий работы с документами

1. Прикрепить два документа к сообщению и попросить сравнить их. Инструмент получает исходные байты вложений, а не пересказ модели. Альтернатива — выбрать два локальных файла кнопками внутри виджета или веб-пилота.
2. Посмотреть документы A и B рядом, выбрать изменение в списке или на странице и перейти к соответствующим фрагментам.
3. Прочитать точное описание изменения и исходные цитаты в панели. Замены, добавления, удаления, точные перемещения и изменения разбиения строк различаются по типу.
4. Нажать «Объяснить в ChatGPT». При поддержке host bridge в чат передаются идентификатор сравнения, выбранная правка, имена файлов, координаты и цитаты. Ответ ChatGPT появляется в разговоре. В обычном браузере или при отсутствии этой возможности подготавливается вопрос для копирования.

PDF отображается как исходная страница на canvas, поверх которой показываются привязки найденных текстовых изменений. DOCX отображается через браузерную модель абзацев, таблиц, списков, поддерживаемых стилей и изображений; разбиение страниц может отличаться от Word. Кнопка разворачивания использует полноэкранный режим только при поддержке хоста.

Документный просмотр в этой версии предназначен для чтения и объяснения изменений. Редактирование DOCX/PDF и экспорт изменённого документа с оформлением — следующий этап. Кнопки принятия правок, undo/redo и скачивания TXT относятся к сохранённому режиму «Тексты».

## MCP-инструменты

| Инструмент | Доступность | Вход и результат |
| --- | --- | --- |
| `open_comparison` | Модель и виджет | Без аргументов; открывает интерфейс выбора файлов, не восстанавливает прежнее сравнение |
| `compare_documents` | Модель и виджет | `originalFile`, `revisedFile`; сравнивает исходные вложения и открывает просмотрщик |
| `get_document_changes` | Модель и виджет | Те же файлы и `comparisonId`; читает следующую страницу изменений или выбранный `changeId` без сброса просмотрщика |
| `compare_uploaded_documents` | Только виджет | `original` и `revised` в форме `{name, data}` с base64; сравнивает файлы, выбранные пользователем в интерфейсе |
| `compare_texts` | Модель и виджет | Точные строки `original`, `revised`, необязательные имена; возвращает diff и открывает текстовый режим |
| `get_text_changes` | Модель и виджет | Те же строки, `comparisonId`, `offset`; возвращает до 80 следующих изменений |
| `apply_text_changes` | Модель и виджет | Те же строки, `comparisonId`, `changeIds`; перепроверяет патчи и возвращает точный итоговый текст |

`compare_documents` и `get_document_changes` объявляют `_meta["openai/fileParams"]: ["originalFile", "revisedFile"]`. В схеме каждого файлового объекта объявлены все четыре свойства: `download_url`, `file_id`, `mime_type`, `file_name`. Обязательны только `download_url` и `file_id`; два остальных поля необязательны. Не заменять файловый вход текстом, восстановленным моделью.

Список документных изменений выдаётся по 20 элементов, с целевым размером окна 400 UTF-16 code units для каждой стороны. Для одной выбранной правки `get_document_changes` принимает `changeId` и `textOffset` и выдаёт окна с целевым размером 10 000 code units. Поля `truncated`, `start`, `end` и `nextOffset` показывают границы цитаты; начало и конец не разрезают суррогатную пару. По усечённым цитатам нельзя делать выводы о пропущенной части. При чтении новой страницы документы загружаются и сравниваются заново, а fingerprint проверяется: изменённые файлы требуют нового сравнения.

Модель получает ограниченные доказательства и сведения о покрытии в `structuredContent`. Полные исходные данные и координаты для отображения передаются только интерфейсу через `_meta.documentComparison`. Идентификаторы правок связаны с SHA-256 конкретной пары документов. Текст документа остаётся данными, а не инструкциями для модели.

Сервер: `POST /mcp`, discovery `2026-07-28`, legacy initialize `2025-06-18`, tools и resources. UI-ресурс: `ui://ctt/review-v2.html`, MIME `text/html;profile=mcp-app`; используются `_meta.ui.resourceUri` и совместимый `openai/outputTemplate`. Bridge работает через `@modelcontextprotocol/ext-apps@2.0.4` и согласовывает собственную версию протокола. Полноэкранный режим объявлен вместе с inline-режимом.

## Покрытие и ограничения

| Область | Поддержка и пределы |
| --- | --- |
| Входные документы | DOCX, PDF с текстовым слоем, UTF-8 TXT; до 2 МиБ на файл |
| Извлечённый текст | До 500 000 символов и 2 000 блоков на документ по правилам существующих импортёров CTT |
| PDF | До 100 страниц; сравнивается текстовый слой, а не изображения или оформление |
| DOCX | Сравнивается основной текст, включая поддерживаемые таблицы; колонтитулы не входят в сравнение |
| JSON-запрос | До 6 МиБ фактических байтов, включая base64 локальных файлов |
| Полный snapshot виджета | До 12 МиБ сериализованного JSON; превышение возвращает явную ошибку, а не частичный результат |
| Загрузка вложения | Общий deadline 15 секунд на файл, до двух проверяемых перенаправлений |
| Режим «Тексты» | До 30 000 UTF-16 code units на исходник; результат выборочного применения может достигать 60 000 |

Сканы и страницы PDF без пригодного текстового слоя, защищённые PDF, формы, комментарии и неподдерживаемые структуры возвращают ошибки. OCR не включён. PDF-импорт также ограничивает время чтения и объём извлекаемых элементов. Пословная подсветка ограничена бюджетом существующего движка; при его превышении показывается более крупный фрагмент с соответствующим примечанием, весь извлечённый текст остаётся в результате сравнения.

Сравнение документов следует правилам импортёров: например, TXT разбивается на строки с нормализацией переносов, а один завершающий newline не создаёт дополнительный блок. Стили и оформление DOCX не являются предметом текстового diff. В режиме «Тексты» сравниваются точные исходные строки без такой нормализации; ручной ввод в HTML textarea следует обычному поведению браузера, о замене CRLF/CR на LF при редактировании импортированного текста интерфейс сообщает отдельно.

Исходные DOCX/PDF не изменяются. В текстовом режиме перед применением патчей заново вычисляется diff и проверяются digest и ID: неизвестные, повторные и устаревшие ID отклоняются. Экспорт TXT использует host-mediated `app.downloadFile` при наличии capability; при отказе остаётся копирование. В обычном браузере TXT создаётся локально из UTF-8 байтов.

## Данные и загрузка вложений

Worker не сохраняет документы или серверные сессии, не ведёт журнал содержимого и не вызывает отдельную LLM. Входные файлы обрабатываются в памяти; состояние открытого просмотрщика временное. Файлы и сообщения, переданные через ChatGPT, обрабатываются также самим ChatGPT. Веб-пилот отправляет выбранные файлы серверу приложения для вычисления сравнения. Объяснение выбранной правки использует текущий разговор ChatGPT и явно отделяет фактические изменения от интерпретации.

`attachments.mjs` принимает только HTTPS без userinfo, нестандартных портов и фрагментов URL. Разрешены поддомены `oaiusercontent.com`, `files.openai.com`, OpenAI-prefixed Azure Blob hosts (`oaisdmntpr…`, `oaisdsorpr…`, `sdmntpr…`) и путь `chatgpt.com/backend-api/estuary/content` с вложенными путями. Каждый redirect проверяется заново; cookies и заголовки авторизации не пересылаются. Размер контролируется по фактическому потоку, MIME и расширение сверяются с сигнатурой, затем существующий импортёр выполняет глубокую проверку DOCX/PDF. Подписанные URL, тела ошибочных ответов и сетевые исключения не выводятся пользователю.

Ссылка на вложение может истечь, а новый хост хранения — отсутствовать в allowlist. В этих случаях нужно прикрепить файл заново либо выбрать локальный файл кнопкой в виджете. Произвольная загрузка документов по веб-адресу не реализована.

## Запуск и отдельный deployment

Из корня репозитория:

```sh
npm ci --prefix chatgpt
npm test --prefix chatgpt
npm run build --prefix chatgpt
npm run dev --prefix chatgpt
```

Локальный адрес — `http://localhost:3000`. Модульные тесты также запускаются напрямую:

```sh
node --test chatgpt/*.test.mjs
```

`node chatgpt/stage-site.mjs /absolute/new-template` собирает изолированный шаблон адаптера, замыкание относительных зависимостей CTT и лицензии. Существующая Site identity не копируется и не перезаписывается. Для нового размещения используйте стандартный Sites workflow с `--template-source`, отдельным Site ID и `"capabilities": ["mcp"]`; для обновления сохраняйте ID пилота. Не переносите Site ID основного CTT в этот проект.

Сборка создаёт `dist/server/index.js` с Worker fetch и встроенным HTML/JS/CSS. Проверяется синтаксис окончательного встроенного ES-модуля. PDF/XML-зависимости и их лицензии включены в сборку; `/licenses` отдаёт уведомления о лицензиях. Внешние CDN и шрифты для просмотрщика не требуются. Публичная публикация в каталоге и review не выполнены.

## Проверка версии 0.2

2026-11-16 прошли 45 автоматических тестов. Покрыты точные текстовые патчи и восстановление новой версии, DOCX с кириллицей и таблицами, PDF/DOCX с координатами страниц, перемещения и reflow, ошибочные и превышающие лимит документы, загрузка вложений с allowlist и deadline, устаревшие fingerprint, paging, MCP/API-контракты и точный TXT-экспорт.

В управляемом Chromium проверены локальная загрузка двух DOCX с кириллицей, сохранение заголовков/жирного текста/таблиц, точная подсветка цены и срока, выбор правки и подготовка вопроса с исходными цитатами. Для двух двухстраничных PDF проверены исходные canvas-страницы, подсветка и переход обеих панелей к правке на второй странице. Переключение в прежний текстовый режим и выборочное применение одной правки также пройдены. Сквозной сценарий с настоящими вложениями разговора и объяснением через ChatGPT host bridge ещё не подтверждён; его нельзя считать проверенным только по корректности MCP-схемы. Предыдущий текстовый пилот прошёл браузерный сценарий выбора правок, undo/redo и побайтового TXT-экспорта; пользователь подтвердил работу плагина в ChatGPT.

## Совместимость интерфейса 0.2.1

Старый `ui://ctt/review-v1.html` продолжает возвращать совместимый просмотрщик: ранее открытый чат может сохранить этот URI в описании `compare_texts`. Текущие инструменты используют `review-v2.html`. Не удалять опубликованные URI при следующем обновлении. `open_comparison` позволяет явно запросить открытие интерфейса и сообщает отдельный веб-адрес для клиентов без виджета; переход туда не переносит документы из чата.

Для диагностики Worker записывает только фиксированные имена MCP-методов и инструментов, версию и категорию UI-ресурса (`current`, `legacy`, `unknown`). Аргументы, тексты, имена файлов, ID пользователей и URL вложений в эти события не включаются. Успешный расчёт инструмента или обычный ответ модели сам по себе не подтверждает появление UI: проверять загрузку ресурса и видимую карточку отдельно.
