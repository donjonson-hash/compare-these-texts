# Compare Two Texts — ChatGPT pilot 0.1

Приватное MCP-приложение для точного сравнения двух текстов и сборки результата из выбранных правок. Адаптер импортирует существующий `src/text-diff.mjs`: исходный движок, сайт и расширения CTT не изменяются.

## Возможности

- Две точные строки или локальные UTF-8 TXT / MD в интерфейсе.
- Подсветка замен, вставок и удалений; переход к фрагменту с номерами строк.
- Применение выбранных правок к исходной версии A, отмена и повтор.
- Экспорт `result.txt`, копирование и просмотр полного результата.
- MCP Apps UI через `@modelcontextprotocol/ext-apps@2.0.4`.
- Stateless Worker: приложение не сохраняет документы, не вызывает LLM и не отправляет данные внешним сервисам. Тексты, переданные через ChatGPT, обрабатываются также самим ChatGPT в рамках разговора. Открытие и сравнение в веб-пилоте отправляет тексты серверу приложения для вычисления; постоянного хранилища и журналирования содержимого нет.

## Контракт

| Инструмент | Вход | Результат |
| --- | --- | --- |
| `compare_texts` | `original`, `revised`, необязательные `originalName`, `revisedName` | SHA-256 пары, сводка, первая страница точных изменений, виджет |
| `get_text_changes` | те же тексты, `comparisonId`, `offset` | до 80 следующих изменений; без сброса виджета |
| `apply_text_changes` | те же тексты, `comparisonId`, `changeIds` | проверенный итоговый текст и выбранные ID |

Смещения — индексы UTF-16, строки — с 1. Перед применением движок заново вычисляет diff и проверяет digest, неизвестные и повторные ID. Изменённый исходник требует нового сравнения. Пустой список выбранных изменений возвращает оригинал; все ID возвращают точную новую версию. Переносы строк, пробелы, BOM и завершающий newline не нормализуются. Ручной ввод в HTML textarea следует обычному поведению браузера; импортированный файл сохраняет оригинальные переносы в состоянии приложения, пока пользователь не редактирует его вручную.

Модель получает доказательства в `structuredContent`, а полный snapshot интерфейса — в `_meta`. Тексты документа считаются данными, а не инструкциями. UI-ресурс: `ui://ctt/review-v1.html`, MIME `text/html;profile=mcp-app`. Объявлены стандартная `_meta.ui.resourceUri` и совместимый `openai/outputTemplate`.

MCP: `POST /mcp`, discovery `2026-07-28`, legacy initialize `2025-06-18`, tools и resources. UI bridge самостоятельно согласовывается SDK по своему протоколу. Скачивание в ChatGPT использует `app.downloadFile` только при наличии capability хоста; при отказе остаётся копирование. В обычном браузере файл создаётся локально как UTF-8 Blob.

## Границы пилота

- До 30 000 UTF-16 code units на каждый исходник, JSON-запрос до 512 KiB. Итог при частичном выборе может содержать до 60 000 code units и скачивается полностью.
- Пределы существующего движка ограничивают затраты. Если точная пословная подсветка слишком дорога, `coarse: true` явно показывает целую замену без потери текста.
- PDF, DOCX, OCR, верстка и прямая загрузка вложений из разговора пока не реализованы. Не подменять оригинал файла пересказом модели.
- Состояние вкладки временное: перед закрытием скачайте результат. Серверных сессий нет.
- Это приватный пилот. Публичное размещение в каталоге и review не выполнены.

## Локальный запуск

Из корня репозитория:

```sh
npm ci --prefix chatgpt
npm test --prefix chatgpt
npm run build --prefix chatgpt
npm run dev --prefix chatgpt
```

Откройте `http://localhost:3000`. Тесты ядра и API можно запустить без установки зависимостей:

```sh
node --test chatgpt/core.test.mjs chatgpt/server.test.mjs
```

## Отдельный deployment

`node chatgpt/stage-site.mjs /absolute/new-template` собирает изолированный шаблон только из адаптера, авторитетного diff-модуля и лицензии. Затем используйте стандартный Sites workflow с `--template-source`, новым Site ID и `"capabilities": ["mcp"]`. Не переносите Site ID основного CTT. Сборка создаёт `dist/server/index.js` с Worker fetch и полностью встроенным HTML/JS/CSS, без CDN или внешних шрифтов.

Не добавляйте `.openai/hosting.json` приватного пилота в корень основного CTT: его deployment независим. Обновления шаблона можно копировать тем же staging script; он не изменяет существующую Site identity.

## Проверка релиза

Автоматические сценарии включают:

1. Точное сравнение и выборочная замена; непринятые правки сохраняют A.
2. Повторяющиеся фразы с отдельными привязками и вставки между равными фрагментами.
3. Пустые тексты, вставки и удаления по краям.
4. CRLF, одинокий CR, newline в конце, табуляции, Unicode и emoji.
5. Полное применение воспроизводит B, включая 150 сгенерированных пар и coarse fallback.
6. Устаревший digest и неизвестные/повторные ID отклоняются.
7. Слишком длинные тексты, неверные типы, непарные суррогаты и превышение фактического HTTP body отклоняются.
8. Содержимое `<script>` остаётся текстовыми данными, не попадает в HTML ресурса.

MCP/API тесты проверяют discovery, initialization, resource metadata, paging, compare → apply и точные байты TXT-экспорта. Браузерную проверку и фактический тест в ChatGPT следует фиксировать отдельно: наличие корректного bridge само по себе не подтверждает поддержку всех возможностей конкретным хостом.

Проверено 2026-11-16: 21 автоматический тест; сборка проверяет синтаксис уже встроенного в HTML JavaScript. В управляемом Chromium пройден пример договора (выбор 2 из 5 правок, undo/redo, применение всех), импорт UTF-8 TXT и скачивание. Скачанный файл с BOM, CRLF, emoji и завершающим переносом побайтово совпал с ожидаемой новой версией. Рендер и скачивание внутри настоящего ChatGPT-хоста пока не подтверждены; мобильный viewport отдельно не проверялся.
